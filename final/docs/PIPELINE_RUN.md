# Reproducible Final Database Pipeline

This document describes how to build the final `sf_rent_board` database from
the complete team CSV. The optional sample workflow is included only for local
debugging; it must not be used for the graded final database.

Run these commands from the repository root. Replace `CSV_PATH` with the exact
full CSV snapshot agreed on by the team.

## 1. Set paths

```bash
CSV_PATH="/absolute/path/to/Rent_Board_Housing_Inventory_20261001.csv"

SAMPLE_CSV="final/database/generated/Rent_Board_Housing_Inventory_sample_100.csv"
SAMPLE_CLEANED_DIR="final/database/generated/sample_cleaned"
SAMPLE_LOAD_DIR="final/database/generated/sample_load"
FULL_CLEANED_DIR="final/database/generated/cleaned"
FULL_LOAD_DIR="final/database/generated/load"
```

The CSV is not stored in the repository. Each teammate should use the same
verified dataset version.

## 2. Optional 100-row test sample

This is only for debugging the pipeline locally:

```bash
mkdir -p "$(dirname "$SAMPLE_CSV")"

python3 - "$CSV_PATH" "$SAMPLE_CSV" <<'PY'
import csv
import sys

source_path, sample_path = sys.argv[1:]
csv.field_size_limit(10**9)

with open(source_path, encoding="utf-8-sig", newline="") as source, \
     open(sample_path, "w", encoding="utf-8", newline="") as output:
    reader = csv.reader(source)
    writer = csv.writer(output)
    writer.writerow(next(reader))
    for _, row in zip(range(100), reader):
        writer.writerow(row)
PY
```

Do not use `SAMPLE_CSV` for final analysis or presentation results.

## 3. Generate cleaned outputs

For optional sample testing:

```bash
python3 final/database/clean_inventory.py \
  --source "$SAMPLE_CSV" \
  --output-dir "$SAMPLE_CLEANED_DIR"
```

For the final complete dataset:

```bash
python3 final/database/clean_inventory.py \
  --source "$CSV_PATH" \
  --output-dir "$FULL_CLEANED_DIR"
```

## 4. Generate the MySQL loader

For optional sample testing:

```bash
python3 final/database/load_3nf.py \
  --source "$SAMPLE_CSV" \
  --output-dir "$SAMPLE_LOAD_DIR"
```

For the final complete dataset:

```bash
python3 final/database/load_3nf.py \
  --source "$CSV_PATH" \
  --output-dir "$FULL_LOAD_DIR"
```

Each run creates `load_3nf.sql`, staging TSV files, and a
`quality_issues.csv` file. The generated SQL contains absolute local paths, so
each teammate should generate it on their own computer.

## 5. Create and load the database

1. Run `final/database/schema.sql` in MySQL Workbench.
2. Confirm that `LOCAL INFILE` is enabled for both MySQL and Workbench.
3. Run `final/database/generated/load/load_3nf.sql` for the complete dataset.
4. Confirm that every generated row-count verdict is `ok` and every orphan
   count is zero.

To enable local loading when necessary:

```sql
SHOW GLOBAL VARIABLES LIKE 'local_infile';
SET GLOBAL local_infile = 1;
SHOW GLOBAL VARIABLES LIKE 'local_infile';
```

Workbench may also require `OPT_LOCAL_INFILE=1` in the connection's Advanced
settings before reconnecting.

If a load fails partway through, rerun `final/database/schema.sql` before
retrying. It recreates the database from a clean state.

## 6. Validate before running analysis

At minimum, verify the total report count and foreign-key integrity:

```sql
USE sf_rent_board;

SELECT COUNT(*) AS total_reports FROM UnitReport;

SELECT COUNT(*) AS orphan_rent_bands
FROM UnitReport ur
LEFT JOIN RentBand rb ON rb.rent_band_id = ur.rent_band_id
WHERE ur.rent_band_id IS NOT NULL AND rb.rent_band_id IS NULL;

SELECT COUNT(*) AS null_vacancy_dates
FROM UnitReport
WHERE vacancy_date IS NULL;
```

For the 2026-10-01 full extract, the expected `UnitReport` count is 551,551.
Use the row counts generated by your own CSV snapshot as the final authority.

After these checks pass, run the SQL files in `final/sql/` against this
database.
